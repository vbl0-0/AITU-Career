# AITU Career: запуск и демонстрация

Реализован модульный FastAPI-бэкенд, React + TypeScript-интерфейс и PostgreSQL. Исходное техническое задание сохранено в docs/ORIGINAL_PROJECT_SPECIFICATION.md.

## Быстрый запуск с Docker

Нужны Docker с Compose и Python 3 для одноразового создания конфигурации.

```bash
python scripts/setup_env.py
docker compose up --build
```

Сайт: http://localhost:8080. API и Swagger: http://localhost:8000/docs.

Скрипт генерирует пароли и JWT_SECRET в `.env`. Повторный запуск сохраняет существующий файл. Бэкенд ждёт PostgreSQL, применяет миграции и загружает данные. Docker volume сохраняет базу между перезапусками.

`.env` и локальная база исключены из Git. Не публикуйте этот файл. Для запуска без Python можно скопировать `.env.example` в `.env`, задать случайные POSTGRES_PASSWORD, JWT_SECRET (не менее 32 символов), DEMO_PASSWORD (не менее 10 символов) и обновить DATABASE_URL для локального запуска.

## Локальный запуск на Windows

Нужны Python 3.12+, Node.js 22.12+ и установленный PostgreSQL. На текущем компьютере его программы находятся в `D:\postgres\bin`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1 -PostgresBin 'D:\postgres\bin'
```

Скрипт создаёт отдельный кластер `.local/postgres`, доступный только на `127.0.0.1:55432`, и базу `aitu_career`. Существующие службы и базы PostgreSQL не изменяются. После установки зависимостей применяются миграции и seed; серверы запускаются в фоне без дополнительных окон.

Сайт: http://localhost:5173. Swagger: http://localhost:8000/docs.

Повторный запуск без переустановки зависимостей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1 -SkipInstall
```

После изменения бэкенда перезапустите серверы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-local.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1 -SkipInstall
```

Логи находятся в `.local`. Скрипт остановки завершает только записанные процессы приложения; отдельный PostgreSQL остаётся запущенным. Остановка именно кластера проекта:

```powershell
& 'D:\postgres\bin\pg_ctl.exe' stop -D '.local\postgres' -m fast
```

## Ручной запуск на другой системе

Создайте базу PostgreSQL, настройте DATABASE_URL в `.env` и выполните:

```bash
python scripts/setup_env.py
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
pip install -r backend/requirements.lock.txt
cd backend
alembic upgrade head
python -m app.database.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на `127.0.0.1:8000`; браузер работает с одним origin.

## Демонстрационные аккаунты

Все четыре аккаунта используют пароль из `DEMO_PASSWORD` в локальном `.env`:

| Email | Назначение |
|---|---|
| student.demo@aitu.edu.kz | Выпускник, Backend Developer |
| analyst.demo@aitu.edu.kz | Выпускник, Data Analyst |
| frontend.demo@aitu.edu.kz | Выпускник, Frontend Developer |
| admin.demo@aitu.edu.kz | Администратор |

Seed создаёт 30 реалистичных **вымышленных** вакансий по 13 направлениям, 69 навыков по 9 категориям, синонимы, профили, проекты, опыт, сертификаты и сохранённые результаты анализа с рекомендациями. Вакансии помечены как демонстрационные и не выдаются за действующие предложения работодателей.

Повторный seed не дублирует исходные записи и не перезаписывает пользовательские профили или пароли. Изменение DEMO_PASSWORD не меняет пароль уже созданного аккаунта. Самостоятельная регистрация создаёт только выпускников.

## Чистая база без демонстрационных данных

Перед первым запуском задайте `SEED_DEMO=false` в локальном `.env`. Обычный запуск
применит миграции и создаст системные справочники навыков, направлений и категорий,
сохранив пустыми вакансии и пользовательские аккаунты. Этот флаг не удаляет уже
существующие демоданные.

Для создания администратора выполните из `backend/`:

```powershell
..\.venv\Scripts\python.exe -m app.database.bootstrap --email your.name@aitu.edu.kz --name "Platform Administrator"
```

Команда запросит пароль без отображения. Пароль должен содержать 10–128 символов;
передавать его аргументом командной строки не нужно. Справочники также будут
инициализированы. Созданный аккаунт использует обычную форму входа и получает
пустой профиль без вымышленных достижений.

Для автоматического запуска можно явно задать `BOOTSTRAP_ADMIN_EMAIL`,
`BOOTSTRAP_ADMIN_NAME` и `BOOTSTRAP_ADMIN_PASSWORD` в окружении сервиса. Локальный
запуск читает `.env`, Docker Compose передаёт эти параметры backend. Новый
администратор создаётся только при явной настройке. После создания пароль можно
удалить из настроек: повторный seed с тем же email сохранит аккаунт и пароль.
Указывать только пароль без email нельзя.

Для автоматизации отдельной команды есть флаг `--password-stdin`: он читает пароль
из одной строки stdin. Повторная настройка существующего активного администратора
сохраняет его имя и пароль. Команда отказывается повышать права существующего
выпускника или активировать заблокированный аккаунт.

После входа администратор может добавлять настоящие вакансии и редактировать
справочники. Для импорта и обновления через официальный API HeadHunter доступны
администраторская форма и отдельная команда; настройка доступа описана в
[VACANCY_IMPORT.md](VACANCY_IMPORT.md). Проверочный поиск сейчас возвращает 403,
поэтому реальные вакансии ещё не загружены.

## Сценарий демонстрации

1. Зарегистрировать новый аккаунт и выбрать Backend Developer в профиле.
2. Добавить образование AITU и навыки Python, PostgreSQL, Docker, Git.
3. Открыть Junior Python Backend Developer.
4. Посмотреть совпавшие, частичные и недостающие навыки; FastAPI будет отсутствовать.
5. Сохранить вакансию и открыть подробный анализ.
6. Добавить FastAPI в навыки. Предыдущий анализ станет устаревшим.
7. Пересчитать оценку и убедиться, что она выросла.
8. Посмотреть карьерный план и вклад компонентов готовности.
9. Войти администратором, добавить/изменить вакансию, справочник или статус пользователя.

## Формула соответствия

```
score = 100 × sum(weight × contribution) / sum(weight)
```

По умолчанию обязательный навык имеет вес 2, желательный — 1. Администратор может задать другие положительные веса. Уровни: Beginner = 1, Intermediate = 2, Advanced = 3. Вклад структурированного навыка — `min(1, user_level / required_level)`; отсутствующего — 0. Семантическая связь или компетенция, найденная только в тексте, получает максимум 0.5. Без извлечённых или заданных требований score = null, а не случайное число.

Пример: четыре полных совпадения из пяти равновесных обязательных навыков дают **80%**. Примерные 85% из исходного задания не подставляются в алгоритм. В подготовленной Python-вакансии дополнительно есть желательный REST API, поэтому знаменатель её оценки равен 11.

Извлечение учитывает границы слов и синонимы: Java не совпадает с JavaScript; JS Programming распознаётся как JavaScript. Название Go распознаётся с учётом регистра, чтобы обычное английское слово `go` не превращалось в компетенцию.

Компетенции выводятся из заявленных навыков, технологий проектов, описаний проектов/опыта и названий сертификатов. Источники показываются в анализе. Предпочитаемые технологии сами по себе не подтверждают владение ими. Оценка относится к навыкам: зарплата, локация, занятость и опыт отображаются отдельно; это не вероятность найма.

## Готовность к трудоустройству

Компоненты нормированы в 0–1:

| Компонент | Вес по умолчанию | Нормирование |
|---|---:|---|
| market | 0.60 | Среднее до пяти лучших совпадений выбранной роли / 100 |
| projects | 0.15 | Доля навыков этих вакансий, указанных в технологиях проектов |
| experience | 0.10 | Дни опыта с релевантными навыками / 180, максимум 1; пересечения учитываются один раз |
| certificates | 0.05 | Число сертификатов с релевантным навыком / 2, максимум 1 |
| education | 0.10 | Заполненность университета, степени, программы и года в наиболее полном образовании |

Итог: `100 × sum(weight × component) / sum(weight)`. Веса настраиваются через `READINESS_MARKET_WEIGHT`, `READINESS_PROJECTS_WEIGHT`, `READINESS_EXPERIENCE_WEIGHT`, `READINESS_CERTIFICATES_WEIGHT`, `READINESS_EDUCATION_WEIGHT`; при Compose добавьте эти переменные в environment бэкенда. Карьерный план показывает вклад каждого компонента. Без вакансий вклад market = 0; без выбранной роли используются все доступные направления.

Это прозрачная эвристика для дипломного проекта, требующая дальнейшей проверки на реальных данных и результатах трудоустройства. Название программы образования не создаёт навыки автоматически.

## Семантический модуль

Основной сценарий не требует сети, внешних LLM API или скачивания моделей. По умолчанию работает словарь и детерминированный алгоритм.

Опционально в виртуальном окружении:

```bash
pip install -r backend/requirements-ai.txt
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2')"
```

Затем установите `SEMANTIC_ENABLED=true` и перезапустите бэкенд. Модель загружается из локального кеша; если библиотека/модель отсутствует или inference завершается ошибкой, используется keyword fallback. Порог SEMANTIC_THRESHOLD по умолчанию 0.85. Семантические совпадения остаются частичными и показывают связанный навык. Перед использованием на реальных данных порог нужно оценить на размеченных парах; метрики качества модели здесь не заявляются.

Для Docker установка библиотек включается через `INSTALL_SEMANTIC=true` при сборке. Модель необходимо предварительно загрузить в контейнер от appuser либо подключить подготовленный кеш в `/home/appuser/.cache/huggingface`; после этого перезапустить сервис. Большая модель не включена в стандартный образ.

Инструмент сравнения алгоритмов запускается без базы данных и без изменения сайта:

## Тесты

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest
..\.venv\Scripts\python.exe -m alembic check
```

API-тесты используют PostgreSQL и реальные миграции в отдельной случайной схеме `test_<uuid>`. В конце схема удаляется. Таблицы приложения не очищаются. Можно задать TEST_DATABASE_URL для отдельной тестовой базы; пользователю БД нужны права CREATE SCHEMA. Unit-тесты проверяют точные оценки, веса, уровни, aliases, источники, semantic partial и fallback.

```bash
cd frontend
npm run build
npx playwright install chromium
npm run test:e2e
```

Для E2E оба локальных сервера должны работать. Альтернативный адрес задаётся через E2E_BASE_URL. Browser-тесты проверяют регистрацию, профиль, образование, навыки, избранное, устаревание анализа, пересчёт, восстановление сессии, выход и мобильную ширину. Тестовые аккаунты создаются с префиксом e2e; очистка использует демонстрационного администратора и удаляет только аккаунты текущего прогона.

## Безопасность и ограничения

JWT живёт 15 минут; access token хранится в памяти React. Refresh secret хранится в HttpOnly SameSite=Strict cookie, а в БД — только его SHA-256. Refresh ротируется; сервер проверяет срок, отзыв сессии, состояние аккаунта и текущую роль при каждом защищённом запросе. Logout отзывает сессию и делает её access token недействительным. Пароли хешируются Argon2id.

Продакшен требует HTTPS, COOKIE_SECURE=true, правильного CORS_ORIGINS, собственных данных, управления первым администратором, резервных копий и ограничения частоты входа на reverse proxy. Текущий вариант предназначен для локальной демонстрации. Университетский прототип и реальные данные работодателей не были предоставлены; сравнительная оценка с ним пока не выполнена.

Документация используемых механизмов: [FastAPI authentication](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/), [Alembic migrations](https://alembic.sqlalchemy.org/en/latest/tutorial.html), [Sentence Transformers similarity](https://sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html).
